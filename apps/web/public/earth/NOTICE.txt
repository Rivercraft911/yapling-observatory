Native cloud tiles for close cameras

NASA Goddard Space Flight Center / Reto Stöckli (clouds); Robert Simmon (compositing enhancements)
https://science.nasa.gov/earth/earth-observatory/the-blue-marble-true-color-global-imagery-at-1km-resolution/
https://www.nasa.gov/nasa-brand-center/images-and-media/

The original western and eastern 21600 × 21600 grayscale PNGs form a 43200 × 21600 global grid, with native angular spacing 1/120 degree and a published nominal1km product class. The242 runtime WebP derivatives preserve that native sampling; each interior is at most2032 × 2032 pixels, with eight real neighboring-pixel gutters. Longitude gutters wrap and pole gutters clamp to original edge pixels. WebP quality90/method4 introduces documented lossy compression. These encoded raster tiles have no resizing, sharpening, inpainting or procedural detail. The source2001 multiday composite, known mosaic boundaries and data limitations are retained. These clouds do not describe the simulated date or measured RF/thermal conditions, and are coarser than the500m regional daytime map.

The curated tile set totals86,643,482bytes. The renderer selects up to nine local tiles from the actual close-camera position, with at most two loads in progress and per-tile size/SHA/dimension checks. Single-channel R8 textures limit cloud tile GPU storage to48MiB including mipmaps, plus at most36MiB retained CPU mask data. Two temporary bitmap/canvas decodes add transient memory. Tiles are released on eviction, after15s outside the needed view, and immediately on view disposal. The matched NASA global 8K/4K map remains outside loaded coverage, near some horizon/polar edges, on failure and in far views. Adjacent tiles use native gutters; exposed coverage edges and camera distance feather to area-reduced coverage from the same NASA composite. Visible cloud opacity and approximate surface shadows share the same sampler, coordinates and tile weights. No runtime external requests occur.

See /earth/cloud-tiles.json for every tile identity, native pixel bounds, complete source hashes, acquisition limits, measured compression errors and licensing. This display-only layer is independent of numerical weather, RF, power and thermal models. No NASA endorsement is implied.

Matched global NASA cloud coverage

The global earth-clouds-nasa-8k.webp (8192 x 4096) and earth-clouds-nasa-4k.webp (4096 x 2048) maps use the exact same checked NASA 2001 western and eastern source images as the native cloud tiles. Each native grayscale hemisphere receives the documented display transfer below before area reduction with Pillow BOX resampling to 4096 x 4096; the halves join west then east. The 4K map is an additional 2 x 2 BOX reduction of the 8K map. Lossless WebP encoding preserves every reduced coverage value exactly, with equal red, green and blue channels. No sharpening, gap filling, altered polar coverage or procedural detail is added. Native blank areas and mosaic artifacts remain. These maps retain the NASA credits, imagery-use terms and observation limits given above.

The original western and eastern NASA images contain a hard cloud-coverage join at longitude 0 degrees over the Southern Ocean. That fixed geographical seam remains in both the global maps and native tiles. It exists in the checked source pixels before resampling or rendering and is separate from the corrected camera-dependent switch between cloud composites. No source pixels were painted in to conceal it.

Using a single source composite avoids switching between different cloud coverage when camera LOD changes. The current TextureLoader stores these global maps as RGBA8 and samples red with NoColorSpace; GPU storage with mipmaps is about 170.67 MiB for 8K or 42.67 MiB for 4K, the same format budget as the previous global maps. Native tiles retain their separately recorded R8 storage. Lossless global encoding and lossy native-tile encoding can differ at individual pixels, and downsampling removes high-frequency detail. Source dates do not describe simulated-time weather. See /earth/cloud-global.json for complete source and runtime SHA-256 identities, transformations, dimensions and round-trip checks.

The 4096 x 4096 lossless WebP is an exact native crop of the 21600 x 21600 A1 grayscale GeoTIFF, matching the regional daytime bounds above. GeoTIFF tags establish EPSG:4326, PixelIsArea, a (-180,90) upper-left edge and 1/240 degree spacing. NASA describes this product class as 500 m. Its angular grid is 6.4 times finer per axis than the 13500 x 6750 global night map; physical east-west spacing varies with latitude. All three source channels are equal and the derivative preserves those grayscale values exactly, with no resize, sharpening or synthetic detail. The 2016 composite retains its original blooming, saturation and processing limitations.

Only the reviewed 399,288-byte derivative is bundled. The 21,888,381-byte LZW source remains in private source storage. Source and runtime SHA-256 identities, crop coordinates, georeferencing, codec versions and reproduction command are in night-detail.json; scripts/build_night_detail.py reproduces and verifies the derivative from the checked source. NASA imagery-use terms and acknowledgment apply; no NASA endorsement is implied.

A close visible West Coast camera lazy-loads one R8 texture with a complete mip chain, bounded to 21.33 MiB GPU plus 16 MiB retained CPU texels for context restoration. The decode uses a temporary 64 MiB RGBA bitmap and 128-row readback strips. Camera distance, geographic edges and asynchronous arrival fade into the existing global fallback in linear light. The existing display curve, tint, emission gain, day/night fade and cloud occlusion apply unchanged. The layer cancels unneeded work, releases the texture after 15 seconds outside coverage, and releases it immediately on view disposal. Smaller GPUs and failed loads keep the global imagery. This is static display artwork, separate from calibrated radiance, simulated-date activity, RF, electrical power, weather and thermal calculations.


Display transfer for NASA cloud artwork, 26 October 2026

The native source image contains low-gray swath plateaus with sharp composite boundaries. In the matched North Atlantic example, broad plateaus around7/255 and13–20/255 became visible pale white overlays when their image codes were used directly as linear alpha. The same shapes exist in the original NASA PNG before tiling or rendering. This is separate from the known longitude0 seam and the earlier mismatch between cloud composites.

Runtime native decoding now applies a monotone soft toe to each grayscale texel before GPU mip generation: t=min(1,c/64), output=floor(c*t*t*(3-2*t)+0.5), where c is the source8-bit image code. Codes64–255 stay unchanged. This display choice reduces low-gray source artifacts and genuine faint clouds; it is not a measured cloud fraction, optical depth or source-required gamma correction. Codes0–9 quantize to0. Neither geography nor cloud locations are painted, generated or sharpened, and stronger original mosaic boundaries may remain.

The matched8K/4K global maps were regenerated from the same checked NASA W/E originals with this exact round-half-up transfer before all BOX area reductions. Applying the transfer before filtering preserves the area contribution of sparse bright wisps. Global runtime samples therefore receive no second transfer. Both LODs share the same recorded transfer and the same alpha/shadow sampler. The242 encoded native tile files, original source bytes/hashes, NASA credits and use terms remain unchanged; the retained old global identities are in Git history.8-bit quantization and native lossy-compression differences remain.

See cloud-tiles.json and cloud-global.json for the transfer, complete identities and acquisition limits. scripts/build_cloud_coverage.py reproduces the global files from the checked originals, validates lossless output, and records actual native-footprint filter-order checks. These changes affect display artwork only and do not enter numerical weather, RF, electrical power or thermal calculations.
